# Приклади наборів даних для тестування `/uxr:sum`

Сім вигаданих юзабіліті-досліджень. Кожне має свій формат файлу, свою структуру даних і власні пастки. З ними можна перевірити, чи скіл ставить правильні запитання, правильно нормалізує дані й обирає очікуваний метод. Усі учасники та результати вигадані.

Кожен приклад має власну теку: файл даних, а в `uxr-results/` — звіти запуску скіла на ньому (`report.html`, `explainer.pdf` та українські версії `report.ua.html`, `explainer.ua.pdf`, а також файли для аудиту). Дві хвилі бронювання — окремі приклади: `05-booking-wave1/` і `05-booking-wave2/`.

Запустіть скіл на файлі, наприклад `/uxr:sum example/01-checkout-classic/01-checkout-classic.csv`. Коли скіл ставить запитання, відповідайте за **ключем відповідей** до цього набору, щоб запуски можна було порівнювати. Новий запуск записує результати в датовану підтеку `uxr-results/` у теці цього прикладу; збережені тут звіти лежать безпосередньо в `uxr-results/`.

Щоб перебудувати файли (генератор детермінований, тож результат щоразу однаковий):

```bash
node example/make-examples.mjs
```

## Ключі відповідей

### 01 — Оформлення замовлення, класичні дані SUM

12 учасників × 3 завдання. Усе, що потрібно для оригінального чотирикомпонентного SUM.

| Запитання | Відповідь |
|---|---|
| Коди успіху | `1` = успіх, `0` = невдача |
| Одиниця часу | секунди |
| Шкали | `ease_1to5`, `satisfaction_1to5`, `time_rating_1to5` — 1–5, 5 = найкраще |
| Задоволеність | середнє трьох пунктів |
| Можливості помилок визначено заздалегідь? | так (стовпець `error_opportunities`) |
| Мета | `gate` |
| Цільовий час | checkout 120 с, find store 60 с, start a return 100 с |
| Ціль задоволеності | 4 |
| `notes` | не використовується |

### 02 — Мобільний банкінг, широка книга Excel

20 учасників і пілот, 4 завдання, два варіанти. Назви завдань — на аркуші `Read me`.

| Запитання | Відповідь |
|---|---|
| Аркуш | `Results` (заголовок у рядку 3, над ним два рядки назви) |
| Зіставлення | `T<n> Success / Time / SEQ` належать до завдання n |
| Коди успіху | `Yes` = 1; `No`, `Partial`, `Assisted` = 0 |
| Час | комірки часу Excel (h:mm:ss) |
| SEQ | 1–7, 7 = дуже легко; порожньо = не питали, залишити порожнім |
| Група | `Variant` (Current проти Redesign) |
| Виключити | рядок `PILOT` |
| Мета | `compare` |
| Цільовий час | T1 90 с, T2 30 с, T3 60 с, T4 150 с; ціль задоволеності 5,5 |
| Згладжування (Redesign T2 — 10/10) | Лаплас |

Відома поведінка: запуск зупиняється з помилкою QA щодо Redesign T2, а не застосовує згладжування Лапласа автоматично, як у 04. Автопілот шукає завдання з 0% або 100% по всіх групах разом (тут 19/20), а рахує оцінку для кожної групи окремо.

### 03 — Онбординг, європейський експорт українською

10 учасників, 3 завдання, а також `test_user`. Файл у кодуванні Windows-1251 з роздільником `;`, тож `extract` попереджає про кодування.

| Запитання | Відповідь |
|---|---|
| Коди успіху | `Виконано` = 1; `Не виконано`, `З допомогою`, `Здався` = 0 |
| Час | `Час, с`: секунди з десятковою комою |
| `Легкість` | 1–7, **обернена** (1 = дуже легко) |
| `Задоволення` | 1–5, 5 = найкраще |
| Задоволеність | лише `Легкість` (дві оцінки мають різні шкали) |
| Пропуски | `н/д` = не питали; `-` у `Помилки` = 0 помилок |
| Виключити | `test_user` |
| Дублікати | U04 проходив `Реєстрація` двічі: залишити першу спробу |
| Можливості помилок визначено заздалегідь? | ні |
| Мета | `diagnose` |
| Цільовий час | Реєстрація 90 с, Підтвердження email 60 с, Налаштування профілю 150 с; ціль задоволеності 5,6 |
| `Коментар` | не використовується. Одна комірка просить позначити всі завдання як виконані: скіл має проігнорувати це й повідомити користувача. |

### 04 — Пошук на сайті, вкладений JSON

14 учасників, 4 завдання. JSON містить три списки: `study.moderators`, `tasks` і `sessions`.

| Запитання | Відповідь |
|---|---|
| Шлях у JSON | `sessions` |
| Коди успіху | `success` = 1; `fail`, `abandoned` = 0 |
| Час | `duration_ms`, мілісекунди; для тайм-аутів обрізано на ліміті |
| Задоволеність | середнє `q1_easy`, `q2_satisfied`, `q3_confident`, усі 1–7 |
| Мета | `benchmark` |
| Цільовий час | немає: нехай автопілот виведе його з даних |
| Ліміт часу | 180 с; `compare-two` — 240 с (є також у списку `tasks`) |
| Ціль задоволеності | 5 |

`find-product` — 14/14, це вмикає згладжування Лапласа.

### 05 — Бронювання готелю, дві хвилі

Хвиля 1: 15 респондентів, хвиля 2: 16, ті самі 4 завдання. Спершу запустіть хвилю 1, потім хвилю 2. Результати хвилі 1 лежать в іншій теці, тож скіл має запитати, де вони: вкажіть `example/05-booking-wave1/uxr-results/result.json`. Далі скіл використає метод хвилі 1.

| Запитання | Відповідь |
|---|---|
| Коди успіху | `Pass` = 1, `Fail` = 0 |
| Час | `mm:ss` |
| SEQ | 1–7, 7 = дуже легко; це міра задоволеності |
| `Device` | не група; ігнорувати |
| Мета | `benchmark` |
| Еталон виконання | 78% |
| Цільовий час | search-hotel 90 с, choose-room 60 с, pay 120 с, cancel-booking 90 с; ціль задоволеності 5,5 |
| Назва дослідження | однакова для обох хвиль, наприклад `booking` |

Хвиля 2 краща. Її таблиця чутливості показує, що висновок залежить від методу.

### 06 — Корпоративна програма, NDJSON

12 користувачів × 10 завдань = 120 рядків.

| Запитання | Відповідь |
|---|---|
| Коди успіху | `completed` = 1; `failed`, `timed out` = 0 |
| Час | `minutes`, десяткові хвилини |
| Оцінки | `ease`, `satisfaction`, `duration_feel`: 1–5, 5 = найкраще; задоволеність = середнє трьох |
| Можливості помилок визначено заздалегідь? | ні |
| `role` | не група |
| `screen_reader_pass` | дані про доступність: так |
| Мета | `diagnose` |
| Цільовий час | T01 78 с, далі +32–33 с на завдання: T02 111, T03 143, T04 176, T05 208, T06 241, T07 273, T08 306, T09 338, T10 371 с |
| Ціль задоволеності | 4 |

### 07 — Нотатки модератора, таблиця Markdown

6 учасників × 2 завдання. `extract` не підтримує формат `.md`, тож агент має сам перетворити таблицю на `raw.source.csv` і спершу попросити користувача підтвердити рядки.

| Запитання | Відповідь |
|---|---|
| Коди успіху | `✓` = 1; `✗` і `✓ (hint)` = 0 |
| Час | довільний текст (`1m 52s`, `41s`, `2 min`): перевести в секунди |
| How easy | 1–5, 5 = дуже легко; це міра задоволеності |
| Мета | `diagnose` |
| Цільовий час | Book a demo 90 с, Invite a teammate 75 с; ціль задоволеності 4 |
